## 二、需要新增/修改的功能（按优先级）

### P0 · 阻断项（2 周内，不做则后面全是空转）

#### F1. 支付网关缺失 —— 付费转化在数学上等于 0

- **现状**：`app/subscription/` 已有完整的套餐配置（月/季/年卡，`service.py:28-32`）、订单号生成、`fulfill_order` 幂等续期、会员到期判断、订单列表。**唯独没有支付回调**——只有 `POST /api/subscription/dev_activate`（`api.py:61`），即开发用的白嫖激活。`service.py:14` 注释也写明"支付网关(支付宝)不在这层"。
- **后果**：报告 KPI 里"付费转化 3–5%"、"6–12 月 ROI"全部无法成立。用户点了套餐，走不到付款。
- **要做**：接支付宝当面付/手机网站支付（个人主体可申请）→ 新增 `POST /api/subscription/notify` 异步回调（验签 + 幂等）→ 回调内调既有 `fulfill_order`。业务层已经写好了，**只差网关这一层**，工作量小但优先级最高。
- 附带：`dev_activate` 上线前必须用环境变量开关关死。

#### F2. AI 每日复盘：全站最大的被埋没资产（这条报告完全没看见）

- **现状**：每交易日 17:45 自动生成一篇基于真实落库数据的市场复盘长文（指数/板块/涨停梯队/成交额/涨跌榜/AI 战绩）。**这本身就是一台已经在跑的内容引擎**——报告花了整节（§4）规划"12 周 14 篇人工内容"，而这里每天自动产出一篇。
- **两个致命问题**：
  1. **所有历史复盘共用一个 URL**。前端用 hash 路由（`app/static/js/daily_review.js:219,232-238`），`/daily_review#2026-07-08` 的 `#` 后面搜索引擎不识别为独立页面 → 上百篇内容在搜索引擎眼里只有 1 页。
  2. **正文由 JS 拉取**（`daily_review.html` 的 `#drContent` 是空 div，靠 `/api/daily_review/{date}` 填充）→ 爬虫抓到空壳。**这才是报告说的"SPA 索引风险"的真实位置**，但只在这一个页面上。
- **要做**：
  - 新增路由 `GET /daily_review/{review_date}` 真实路径（保留 `#hash` 301 兼容）
  - 服务端把复盘正文（免费部分）直接注入 HTML 再返回，付费部分继续 JS 拉
  - sitemap 动态收录每一天的复盘 URL + `lastmod`
  - 每页加 `Article` + `BreadcrumbList` JSON-LD
- **价值**：一次改造 ≈ 报告里"内容中心 + 14 篇内容"的大半，且零边际人力成本。AI 热门板块（`/ai_hotsector`）同理，可复用同一套。

#### F3. 全站无 canonical、无结构化数据

- **现状**：grep 确认 `canonical` / `application/ld+json` / `schema.org` **全站 0 处**。
- **要做**：每页 `<link rel="canonical">`；首页加 `SoftwareApplication`；复盘/热门板块加 `Article`；FAQ 页加 `FAQPage`。低成本高确定性。

#### F4. 首页第一屏就是表单，没有一句话说明这是什么

- **现状**：`index.html:96` 防过拟合检查 checkbox **默认 unchecked**。`app/engine/robustness.py` 已实现参数 ±20% 扰动 + 样本内外拆分，结果渲染也齐全（`app.js:854-890`）。
- **矛盾**：报告把"防过拟合可信"定为核心钩子（我认同，这确实是竞品普遍不做的），而产品把它藏在一个默认关的勾选框里。
- **要做**：默认勾选；结果区加一句人话结论（如"参数扰动后年化波动 <15%，该策略对参数不敏感" / "样本外收益仅为样本内的 30%，疑似过拟合"）。**从"给个表格"变成"给个判断"**，这才是可传播的钩子。

#### F6. 有访问日志，但没有转化归因

- **现状**：`app/visit_log.py` 已在跑，落 `user_visit_log` 表：IP/UA/referer/path/status/设备/地理（`:229-237`）。**缺三样**：无 `user_id`（登录用户与访问日志断链）、无 UTM 参数、无业务事件（回测完成/注册/下单/开通会员）。
- **要做**：**不必上 GA4 + 神策**（报告建议花 ¥1,500/月）。自建表已经在跑且带地理维度，只需：
  - 表加 `user_id`、`utm_source/medium/campaign`（落地时写 cookie，后续请求带上）
  - 新增轻量 `POST /api/event` 记录关键动作
  - `/admin/tasks` 已有运维看板，同页加一个漏斗视图：访客 → 回测 → 注册 → 下单 → 付费
- 这条不做，报告里所有 KPI（CPL、激活率、K 因子）都没法计算。

#### F7. 零分享/导出能力（PLG 无载体）

- **现状**：全库 grep，`share` / `导出` / `toDataURL` **0 处**。用户跑完回测拿不走任何东西。

### F2 → 每日复盘可索引化（本次改动最大的一项）

| 改动 | 说明 |
|---|---|
| 新增路由 `/daily_review/{date}` | 每篇复盘独立 URL，替代原先所有往期共用 1 个 URL 的 `#hash` 方案 |
| 服务端直出正文 | 新增 `app/daily_review/render.py`（Python 版受限 markdown 渲染，与前端 `renderMarkdown` 同款输出）；title/description/canonical/OG 按篇生成 |
| 复盘标题改 `<h1>` | 原先是 `div`，页面没有主标题 |

| 旧 hash 链接兼容 | `/daily_review#2026-07-08` 自动 `replaceState` 改写到新路径，已发出去的链接不失效 |
| sitemap 收录每篇 | 带 `lastmod`，10 分钟缓存；URL 数 8 → 24，且每个交易日 +1 |

**付费墙如何与 SEO 共存**（这块最容易做错）：
- HTML 响应带 ETag、可被共享缓存复用 → **任何按登录态变化的内容都不能进 HTML**。
- 服务端一律按「未订阅」直出：最新一篇全文（本来就免费），往期只出 220 字免费预览 + 付费墙。会员的完整正文由前端拿 API 覆盖。
- 给爬虫和给访客的 HTML **完全一致**，不按 UA 区分（那是 cloaking，会被判罚）；改用 Google 官方的付费墙声明 `isAccessibleForFree: false` + `hasPart.cssSelector: ".dr-paid"`。

**顺带修掉的一个坑**：`get_review()` 在「这天没有复盘」和「连不上数据库」两种情况下都返回 `None`，原样照搬会让 DB 抖一下就给已被索引的 URL 回 404 —— 反复几次会被踢出索引。新增 `db_available()` 区分，连不上回 503（爬虫会择期重试）。同样地，历史列表接口失败时不再清空服务端直出的链接。

### F3 → canonical 与结构化数据

- 8 个可索引页加 `canonical`；`/dashboard`、`/tasks` 两个运维页改为 `noindex,nofollow`。
- 首页加 `SoftwareApplication`（含 featureList 与免费声明）；复盘页加 `Article` + `BreadcrumbList`。
- robots.txt 增加 `Disallow: /static/*.html$`——挡掉与正式路由重复的裸模板文件，CSS/JS 仍允许抓取（渲染需要）。
- **已实测**：CSP 是 `script-src 'self'` 且无 `unsafe-inline`，`application/ld+json` 不是可执行脚本，浏览器不拦截，控制台无 CSP 违规。

### 验证

- 258 个测试通过（新增 30 个：markdown 渲染与转义、付费预览不泄漏全文、付费墙结构化声明、`</script>` 注入、404/503 区分）。
- 浏览器实测：正文直出 1026 字、往期只出 220 字预览 + 付费墙、15 条历史真链接、14 个锁图标、当前篇高亮、旧 hash 自动改写、前进/后退正常、控制台零报错。
- 页面渲染 2–4ms（经 `127.0.0.1`；走 `localhost` 的 2s 是 Windows IPv6 DNS 回退，与应用无关）。
